The session, in six moves

We stop talking and build it. Each team deploys a real Application Gateway with a WAF in front of an app that has no public IP, attacks it, watches the logs, then flips the WAF to blocking and attacks again.

The gauntlet

Five layers, five Terraform phases

Every phase is a self-contained project you can deploy and destroy on its own — each with a diagram of what the request meets there. Phase 2 — the WAF on Application Gateway — is the heart of the lab and works end to end.

One prefix per team. Pass -var="prefix=team1", team2, … so resources never collide — and set ARM_SUBSCRIPTION_ID to a sandbox subscription first. Or deploy the lot with ./create-all.sh team1. Everything bills by the hour: destroy it the same day.

Phase 2 · the centerpiece

The WAF reads the request itself

A network firewall asks "which IP and port?" A web application firewall asks "what is this request actually trying to do?" It reads the URL, headers, cookies and body and blocks known attack shapes — chiefly the OWASP Top 10. Start in Detection to learn real traffic, then switch to Prevention. Never block blind.

# deploy in Detection mode (log only)
terraform apply -var="prefix=team1" -var="waf_mode=Detection"
URL=$(terraform output -raw app_url)

# fire four attacks — all still return 200
curl -i -G $URL --data-urlencode "id=1' OR '1'='1"
curl -i -G $URL --data-urlencode "q=<script>alert(1)</script>"
curl -i --path-as-is "$URL/../../etc/passwd"
curl -i -A "sqlmap/1.7" $URL
# then find yourself in the logs (Log Analytics · KQL)
AzureDiagnostics
| where Category == "ApplicationGatewayFirewallLog"
| project TimeGenerated, clientIp_s, requestUri_s, ruleId_s, action_s
| order by TimeGenerated desc
● 200 · reaches the app

See what would be blocked

Every attack still succeeds, but each one is recorded with the rule ID that matched. That's the point of Detection: you learn real traffic without breaking anyone. Logs take a few minutes to appear.

# flip one variable — only the WAF policy changes, in seconds
terraform apply -var="prefix=team1" -var="waf_mode=Prevention"

# rerun the Round 1 attacks → now 403 Forbidden, app never sees them

# rate limit: burst 150 requests, watch 200s turn to 403s
for i in $(seq 1 150); do
  curl -s -o /dev/null -w "%{http_code}\n" $URL
done | sort | uniq -c
● 403 · blocked at the door

Same attacks, stopped cold

In Prevention the WAF logs and blocks. The injection, XSS, traversal and scanner probes get a 403 and never reach your code. The rate-limit rule caps each client at 100 req/min, so the burst flips to 403 once it crosses the line.

Wrap up

Destroy it, then talk about it

Always tear it down — the gateway bills by the hour. One command does every phase, then debrief the lesson that matters most.

# every phase you deployed, in one go
./destroy-all.sh team1

# or a single phase
terraform destroy -var="prefix=team1"

A WAF reduces risk. It does not replace validation and authorization in your code. No single control is the answer — the stack is. Learn the layer, and the cloud product is just a name.
